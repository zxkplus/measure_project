# 相机-机械臂抓取标定：设计、实现与评估

> 对应代码：`measure/circle_locator.py`、`measure/robot_calibration.py`  
> 测试：`tests/test_circle_locator.py`、`tests/test_robot_calibration.py`  
> 可运行合成演示：`python scripts/robot_calibration_demo.py`

> **HTTP 接口已改为无状态矩阵契约**：视觉/偏移标定各返回一个 3×3 齐次矩阵，`/locate` 由软件传入矩阵。本文保留底层标定数学与 `RobotPickRecipe` 演示；对外接口见 [`measure_api/PICK_API.md`](../measure_api/PICK_API.md) 和 [`measure_api/PICK_MODULE_GUIDE.md`](../measure_api/PICK_MODULE_GUIDE.md)。

## 0. 结论（TL;DR）

1. **整体两段式思路成立**：四点标定建立“图像位移 → 机械位移”的映射；偏移标定建立“相机中心 → 夹爪中心”的修正；最后可以一次移动完成抓取。
2. **但第一阶段的“绝对仿射”不能直接拿来当机械坐标用**。相机在动、标定物不动时，拟合出的 `r = A·p + b` 中，平移项 `b` 绑定的是**这一次标定物所在的物理位置**；换一个目标、或标定物换个位置，`b` 就变了。把当前检测到的 `p` 代入这个绝对仿射，算出来的恰好是**当前机械臂位姿**，移动量是 0，验证会失败（除非目标本来就在画面中心）。
3. 真正可复用、也正好是抓取所需的，是它的**线性部分** `A`（2×2）：

   ```
   Δr = A · Δp
   r_center = r_current + A · (c − p)
   grasp   = r_current + A · (c − p) + offset
   ```

   其中 `c` 是画面中心/主点，`p` 是目标圆心，`offset = A_place − B_center`。
4. 你最后一段说的“不要先移到相机中心再移夹爪，而是直接算相对距离，加上相机到夹爪的偏移，一次移动”，**这个形式是正确的**，代码里的 `RobotPickRecipe.pick_delta()` 就是它。
5. 合成闭环验证结果：A 矩阵误差约 `1e-6`，四点验证残差 `0.02 px`，偏移误差 `0.001 mm`，新目标一次抓取误差 `0.002 mm`。这是**算法下限**，不是真机精度；真机误差主要来自机器人重复性、目标高度/视差、镜头畸变和相机 Z 变化（见第 6 节）。

## 1. 系统假设与坐标约定

本模块假设：

- 相机与夹爪刚性安装在同一个三轴（X/Y/Z）机械臂上；
- 载台固定，机械臂做笛卡尔运动，没有 R 轴旋转；
- 视觉拍照时相机 Z 固定（或至少标定与抓取时的相机 Z 一致）；
- 目标在同一个平面上；标定物与待抓目标的特征高度差固定（可以为 0，见 3.3）；
- 机器人控制器返回的 XY 是同一套机械坐标（单位建议 mm；模块不强制单位，但 `mm_per_px` 按 mm 解释）。

坐标约定：

- 图像坐标 `p = (u, v) = (col, row)`，与 OpenCV 一致；
- 机械坐标 `r = (X, Y)`，单位与控制器一致；
- `A`：2×2，图像位移 → 机械位移（mm/px 量纲）；
- `J = A⁻¹`：机械位移 → 图像位移（px/mm 量纲）；
- `c`：主点，默认取图像几何中心 `((w−1)/2, (h−1)/2)`；
- 相机相对法兰的偏移记为 `K`，夹爪相对法兰的偏移记为 `G`。

> **位姿向量约定（已确认）**：本项目 **Z 轴就是高度轴**，与模块约定 `(X, Y, Z)` 一致：`get_position()`/`move_to()` 的前两个分量是载台平面，第三个分量是高度，不需要适配层。`calib_z` 记录拍摄时的高度；2D 仿射只使用前两个分量，Z 只用于保持/设置高度。

> 注意：`A` 的旋转角通常比“相机安装角”多 180°。因为相机向右移动时，固定目标在画面里向左移动，所以 `Δp` 与 `Δr` 的符号相反。演示中相机安装角 20°，`A` 的 `rotation_deg` 报 −160°，两者相差 180°，这是正常的。

## 2. 四点标定

### 2.1 采数方式

**本项目已确认的采数方式**：标定物手动放在载台上并保持不动，移动机械臂，让标定物出现在画面四个角落附近，记录四次拍摄的机械臂位姿；找圆得到四个图像圆心，构成四组对应点。

标定物固定在载台上，移动机械臂，在不同位姿拍摄同一目标：

```
(p_0, r_0), (p_1, r_1), ..., (p_N, r_N)
```

其中 `p_i` 是第 i 张图里圆心在图像上的坐标，`r_i` 是拍摄该图时的机械臂位姿。建议：

- N ≥ 4，推荐 **7~9 个点**（3×3 网格或四角 + 中心）；
- 让目标在图像上尽量靠近四角，覆盖整个视野；
- 机械臂位姿也要在 XY 两个方向充分展开，避免只沿一个方向移动；
- 最好从两个方向接近同一个点，取平均，以减小反向间隙（backlash）的影响。

### 2.2 关键问题：绝对仿射的平移项不可复用

设标定物在世界坐标为 `W`，相机相对法兰偏移为 `K`，相机像素尺度矩阵为 `H`（mm/px，含旋转）。在法兰位姿 `r` 时：

```
p = c + H⁻¹ · (W − r − K)
```

解出 `r`：

```
r = −H · (p − c) + (W − K)
  = A · p + b
A = −H
b = W − K − A · c
```

`b` 里含有 `W`，也就是标定物的物理位置。换一个目标、或把标定物挪到别处，`b` 就会变。**只有 `A` 是相机安装带来的、与目标位置无关的量。**

#### 一个具体数值例子

取 `s = 0.1 mm/px`、`c = (320, 240)`、`W = (1000, 500)`、`K = (50, 0)`、`G = (0, 0)`：

- 真值：让相机中心对准目标的法兰位姿是 `W − K = (950, 500)`；
- 在 `r = (940, 500)` 拍一张，目标出现在 `p = (420, 240)`；
- 用四点数据拟合绝对仿射 `r = A·p + b`，得到 `A = −0.1·I`；
- 把 `p = (420, 240)` 代入：`A·p + b = (940, 500)`，**就是当前位姿**，机械臂不会动；
- 正确的移动量是 `A·(c − p) = (−0.1)·(320−420, 0) = (+10, 0)`，移到 `(950, 500)`。

所以“检测到 p → 计算对应机械坐标 → 移过去 → 目标应该在画面中心”这个验证，**用绝对仿射是无法成立的**：算出来的坐标就是当前坐标。把公式换成相对形式后，验证才真正有意义。

> **前提说明（本项目已确认）**：本项目采用“标定物固定、移动相机”的方式，因此下面的相对模型适用，绝对仿射的平移项**不可复用**。如果你以后改成把标定物用夹爪放到四个**已知机械坐标**的位置、再拍四张图，那么 `(p_i, 目标机械坐标)` 是真正的绝对对应，绝对仿射的平移项才可用。

### 2.3 正确的模型与指令

对任意目标（新目标也一样），只要它在当前位姿 `r_current` 下成像于 `p`，那么：

```
r_center = r_current + A · (c − p)
```

推导：该目标的（未标定的）绝对仿射为 `r = A·p + b'`，它在 `p = c` 时的位姿就是 `r_center = A·c + b'`；而 `b' = r_current − A·p`，代入即得上式。

这也是为什么 `A` 足以支撑抓取：我们不需要知道目标在载台上的绝对坐标，只需要知道“从当前位姿到相机对准它”的相对移动。

**代码里拟合的是什么？**

- 最小二乘拟合 `r = A·p + b`（6 个未知量），但**只把 `A` 和 `c` 作为可复用产物**；
- `b` 也会存进 JSON，字段名 `translation_xy`，并标记 `translation_reusable: false`，只用于复现/诊断，不参与任何运动指令；
- `ImageRobotCalibration.servo_delta()` / `center_pose()` 只用 `A`。

### 2.4 拟合与鲁棒性

- 最少 3 个点（6 个方程解 6 个未知量，刚好确定）；4 个点开始有冗余；推荐 5 个以上。
- 5 个点以上时启用 **RANSAC（三点最小样本）+ 内点重拟合**，可以剔除一个明显的误检测/离群点。
- **4 个点无法自动剔除离群点**：每 3 个点都能精确确定一个仿射，所有三点模型的“内点数”都是 3，没有冗余来分辨哪个点是坏的。这是四点法的固有局限。工程上建议至少 5 点，最好 7 点。
- 质量指标：
  - `rms_px` / `max_px`：像素残差；
  - `rms_mm` / `max_mm`：换算到机械坐标的残差；
  - `loo_rms_px`：留一交叉验证（新点预测误差，比拟合残差更能反映泛化）；
  - `condition`：机械位姿展开程度，接近共线会很大；
  - `image_coverage` / `image_span_px`：图像点覆盖范围；
  - `anisotropy`：`A` 的两个奇异值之比，明显偏离 1 说明像素非方形/畸变/倾斜；
  - `mirrored`：`det(A) < 0`，说明图像轴相对机械轴有镜像；
  - `rotation_deg`：`A` 的极分解旋转（含 180° 反向，见第 1 节）。

### 2.5 四点验证在验证什么

`verify_image_to_robot()` 做的是：

1. 把目标先放到某个图像位置 `q`（用 `A` 移动）；
2. 检测到 `p`；
3. 执行**一次**修正 `Δr = A·(c − p)`；
4. 再检测，测量目标到 `c` 的残差。

它能抓到：

- `A` 的尺度错误（修正会过冲/不足）；
- `A` 的旋转错误（修正方向偏）；
- 大范围非线性（畸变、倾斜）在检查点的局部误差；
- 检测失败/目标丢失。

它**不能**验证：

- 偏移标定是否正确（需要抓取或夹爪视角检查）；
- 目标高度/视差是否正确（标定物和实际目标高度不同时，这里看不出来）；
- 绝对机械坐标是否正确（本方法本来就不产出绝对坐标）。

另外，当“指令的居中目标”和“验证的判据”都取同一个主点时，主点偏差会在这个闭环里抵消（见 3.3），所以验证通过不代表主点等于几何中心；它只证明 `A` 能把目标伺服到指定像素。

## 3. 偏移标定

### 3.1 定义与符号

- `A_place`：夹爪在目标正上方、放下目标时的法兰位姿（机械坐标 A）；
- `B_center`：相机中心对准目标时的法兰位姿（机械坐标 B）；
- `offset = A_place − B_center`。

物理解释：理想情况下 `offset = K − G`，即**相机中心相对夹爪中心的向量**（在机械坐标里）。但更稳妥的理解是**操作定义**：

```
grasp_pose = camera_centered_pose + offset
```

也就是“从相机对准目标的位姿，加上这个向量，夹爪就在目标正上方”。

> **符号是最容易错的地方**：`offset` 是**加**到相机居中位姿上的，不是减。如果按“夹爪到相机”的直觉存成 `G − K`，那么抓取公式要改成减，两者不能混用。配方 JSON 里写了 `convention: "grasp_pose = camera_centred_pose + offset_xy"`，以它为准。

### 3.2 操作流程（与你的描述一致）

1. 夹爪抓起标定物，手动确认抓稳；
2. 控制夹爪放下标定物，**保持机械臂不动**，记录当前法兰位姿 `A_place`；
3. 手动移动机械臂，让标定物出现在相机视野里；
4. 拍照、找圆，得到 `p`；
5. 计算 `B_center = r_current + A·(c − p)`，移动过去；
6. 再拍一张，确认目标在画面中心（残差 `center_error_px`）；
7. `offset = A_place − B_center`。

代码入口：

```python
offset = calibrate_gripper_offset(
    robot, capture, calibration,
    place_pose=release_pose,   # 省略则用当前位姿（刚放完就调用）
)
```

建议重复 3~5 次，把标定物放在不同位置，用 `combine_offsets()` 取均值并看 `std_xy`。如果几次的 offset 差异大于 0.5 mm，说明标定物没放稳、检测有问题，或机械臂重复性差。

### 3.3 主点、Z 高度与视差

**主点**：本流程里，偏移标定的 `B_center` 是“把目标伺服到主点 `c`”的位姿，抓取指令也用同一个 `c`。因此即使真实光轴不在图像几何中心，这个偏差会在 `offset` 和 `grasp` 之间抵消，**抓取精度不受影响**。主点真正会带来问题的地方是：

- 把 `b` 当绝对坐标解释时；
- 改变相机 Z，或需要做像素尺度换算时；
- 需要和另一个相机/另一个坐标系对齐时。

**Z 高度**：本模块假设三轴笛卡尔机械臂，XY 与 Z 解耦。`offset` 是一个 XY 向量：它由“放置时的法兰 XY”和“相机居中时的法兰 XY”相减得到，在视觉拍照的 Z 高度上使用。对笛卡尔龙门/三轴模组，这个 XY 向量不随 Z 变；对关节臂则不成立。

**视差（固定拍摄高度并不等于没有视差）**：如果标定物和实际目标的特征高度不同，即使相机 Z 全程固定，用“标定物所在平面”的仿射去算实际目标，仍会有视差。设相机到标定物特征面的距离为 `H`，实际目标特征面比标定面高 `h`（低于则为负），实际目标特征点离光轴的距离为 `d`，则平面标定给出的离轴距离会被放大 `H/(H−h)` 倍，误差近似为：

```
Δ ≈ d · h / (H − h)
```

等价地，把“图像偏移 → 机械位移”的映射乘一个高度修正系数：

```
k = (H − h) / H
```

例：`H = 300 mm`、`h = 5 mm`、`d = 30 mm` → `Δ ≈ 0.51 mm`；`k ≈ 0.983`。这往往比算法误差大一个数量级，尤其是目标靠近画面边缘时。

处理方式（按推荐排序）：

1. **垫块**：把标定物垫到与实际目标特征面等高（`h = 0`）。最省事，不引入额外模型。
2. **一次性缩放**：知道 `H` 和固定的 `h` 时，把 `k` 乘到 `A` 的位移映射上（`A_eff = k·A`），并让后续 offset 标定、抓取、验证都用 `A_eff`。当前版本没有内置这个参数；需要的话可以加，或先手工在配方里乘。
3. **只在中心附近抓取**：`d` 小，视差按比例减小；适合精度要求不高的场景。

本模块暂未内置高度补偿；配方会记录 `calib_z`，偏移标定会在视觉 Z 明显偏离时报警，但**不会自动补偿 h**。

### 3.4 可选：offset 与 A 的联合拟合

如果采集了 N ≥ 3 次“放置 + 检测”样本（每次记录 `A_place_i`、检测时的相机位姿 `r_i`、图像点 `p_i`），可以直接拟合：

```
A_place_i − r_i = offset + A · (c − p_i)
```

未知量 6 个（offset 2 + A 4），每次样本给 2 个方程。这样 offset 和 A 是一起优化的，能平均掉单点标定的误差。代码里的 `OffsetSample` 已经保存了 `camera_pose` 和 `image_uv`，为后续加这个联合拟合预留了数据，但当前版本只做 `A_place − B_center` 的均值。

## 4. 找圆算法

### 4.1 流程

1. **粗候选**：Otsu 阈值分割 + 轮廓（暗目标/亮目标/自动两种极性），必要时用 `HOUGH_GRADIENT_ALT` 兜底；
2. **径向亚像素精化**：在候选圆周围沿 N 条射线采样灰度剖面，找径向梯度峰，抛物线插值得到亚像素边缘点；再用代数圆拟合 + 几何 Gauss-Newton 精修，MAD 剔除离群点；第二轮用更窄的搜索带重新居中；
3. **置信度**：由圆度残差、射线支持率、角度覆盖率、对比度信噪比合成，并设硬门槛：
   - `support ≥ min_support`（默认 0.45）
   - `rms ≤ max(0.6, 0.05·r)`（默认 5% 半径）
   - `contrast ≥ min_contrast`（默认 3σ）
   - `confidence ≥ min_confidence`（默认 0.35）

输出 `CircleDetection`，包含 `center`、`radius`、`confidence`、`support`、`coverage`、`rms_error`、`ellipticity`、`contrast`、`reason`。**调用方必须先检查 `valid`，再允许机械臂运动。**

### 4.2 合成测试结果

| 场景 | 结果 |
|---|---|
| 干净圆（r=40 px） | 圆心误差 0.01~0.04 px，置信度 0.96 |
| 高斯噪声 σ=6 | 圆心误差 0.04 px，置信度 0.95 |
| 亮圆/暗背景 | 误差 0.02 px |
| 50% 遮挡 | 误差 0.13 px，置信度 0.68，仍 valid |
| 贴近图像边界 | 误差 0.13 px |
| 方形干扰物 | 拒绝（`not_round + low_confidence`） |
| 随机纹理 | 拒绝（无候选/低支持率） |
| 圆环目标 | 能定位圆心（半径可能落在内/外边缘之一） |

典型耗时：640×480、单个目标约 20 ms；纯噪声触发 Hough 兜底时约 190 ms。

### 4.3 失败模式

- 金属/反光表面的高光会把边缘切成几段 → 支持率下降；建议用哑光/漫反射标定物；
- 低对比度（< 3σ）会被拒绝；
- 多个相似圆同时出现时，靠 `radius_range`、ROI、`expected_center` 先验选择；否则“置信度最高”未必是你要的那个；
- 圆形目标没有方向/ID，不能提供夹爪旋转角；如果夹爪有姿态要求，建议换 ArUco/AprilTag 或加一条标记线；
- 目标被夹爪遮挡时无法在抓取位复检，只能靠外部传感器。

```json
  "gripper_offset": {
    "offset_xy": [8.0, 4.0],
    "convention": "grasp_pose = camera_centred_pose + offset_xy",
    "std_xy": [0.0, 0.0],
    "mean_center_error_px": 0.03,
    "valid": true,
    "samples": [ ... ]
  },
  "locator": { "...": "找圆参数，保证下次检测可复现" },
  "metadata": {}
}
```

要点：

- `robot_per_pixel` 是**唯一**参与运动指令的变换；
- `matrix_3x3` / `translation_xy` 是完整仿射的展示/复现字段，**平移不可复用**；
- `samples` 保留每张图的原始对应关系、残差和内点标记，便于事后审计；
- `locator` 和 `image_size` 一起保证“下次换一个操作员/换一台同型号相机”时检测参数可复现；
- 配方带 `schema`/`version`，加载时会校验版本，未来字段升级可识别。

## 6. 精度评估与误差预算

### 6.1 合成闭环（算法下限）

| 指标 | 结果 |
|---|---|
| `A` 相对真值误差 | ~`1e-6`（旋转+尺度） |
| 四点拟合 `rms_px` | 0.005 px |
| 留一交叉验证 | 0.018 px |
| 四点验证残差 | 0.015 px（均值）/ 0.021 px（最大） |
| 偏移误差 | 0.001 mm |
| 新目标一次抓取误差 | 0.002 mm |
| 抓取位复检残差 | 0.039 px |

这些数字说明**数学链路是自洽的**，但不代表真机精度。

### 6.2 真机主要误差源

| 误差源 | 量级（参考） | 说明/对策 |
|---|---|---|
| 圆心检测 | 0.03~0.2 px | 亚像素 + 高置信度门槛；哑光标定物 |
| 仿射拟合 | 0.05~0.3 px | 7~9 点、覆盖全视野；避免 4 点单点误检 |
| 镜头畸变 | 1~5 px（边缘） | 先做内参去畸变；或缩小工作视野；或改单应 |
| 相机倾斜 | 0.05~0.2 mm | 倾斜时平面映射是单应，仿射只在局部成立；检查残差随半径的系统趋势 |
| 机器人重复性/反向间隙 | 0.02~0.2 mm | 双向接近取平均；多点重复测 |
| 目标高度/视差 | 0.1~1 mm | 标定物与目标等高；或高度补偿 |
| 相机 Z 变化 | 尺度按 `(H−Δz)/H` 变 | 视觉 Z 固定；或标定 `H` 后补偿 |
| 相机安装热漂/松动 | 0.05~0.3 mm | 定期复检四点验证；机械上锁紧 |
| 单位/脉冲换算 | 可能很大 | 确认控制器返回的是 mm，且 A 的量纲一致 |

**经验预期**：在“目标等高、相机 Z 固定、镜头畸变小、机械臂重复性 0.05 mm”的条件下，抓取精度做到 **0.1~0.3 mm** 是合理的；如果目标高度不受控或视野边缘畸变明显，0.5~1 mm 也很常见。建议用“同一目标随机放 20 次，记录抓取偏差”的方式做实测，而不是只看标定残差。

### 6.3 四点法与七点法的差别

- 4 点：6 个未知量、8 个方程，只有 2 个自由度的冗余；一个坏点无法自动识别，且图像覆盖稍差就会放大误差。
- 7 点：14 个方程，可以做 RANSAC/留一验证，残差和泛化误差都能看出来。
- 如果节拍允许，**优先 7~9 点**；四点只作为快速/受限场景的兜底。

## 7. 适用边界（什么时候这套方法会失效）

1. **相机 Z 在标定和抓取之间变化**：透视镜头下 mm/px 会变；除非做高度补偿，否则 A 失效。
2. **目标特征高度与标定物高度不同**：视差误差，见 3.3。
3. **相机光轴明显倾斜**：平面到图像是单应，不是仿射；大视野下会有位置相关的尺度/剪切误差。表现为残差随图像半径系统性增大。
4. **镜头畸变大且未校正**：同上；先做内参标定/去畸变。
5. **机械臂不是笛卡尔三轴**（有关节/旋转）：XY 与 Z 不解耦，offset 会随姿态变；本方法不适用。
6. **有 R 轴/夹爪需要旋转角**：圆目标不提供方向；需要 fiducial 或额外标记。
7. **目标不在同一平面/是三维物体**：取哪个特征点、特征点高度多少，要先定义清楚。
8. **需要“图像坐标 → 载台绝对机械坐标”的通用映射**：仅靠“固定标定物 + 移动相机”的四点数据，数学上无法辨识绝对平移；需要接触式/已知坐标的额外基准（见 7.1）。
9. **动态目标/传送带**：本方法是静态拍照-移动，不含跟踪/延迟补偿。

### 7.1 如果确实需要绝对图像→机械坐标

有两种可行做法：

- **接触式基准**：用探针/夹爪把标定板上的几个点“触碰”出机械坐标，再和图像点配对，拟合绝对仿射/单应；
- **已知放置点**：用夹爪把标定物放到若干个已知机械坐标的位置，每个位置拍一张，拟合“图像点 → 目标机械坐标”的绝对映射。注意这会和夹爪偏移耦合，通常直接拟合“图像点 → 抓取位姿”更实用。

对本项目“拍照 → 抓取”的目标，相对映射 + 偏移已经足够，不需要绝对映射。

## 8. 改进建议（按性价比排序）

1. **先保证高度一致**：给标定物做一个和实际目标等高的垫块；这通常比换算法更能提升精度。
2. **视觉 Z 固定**：标定、检测、抓取前的拍照都用同一个相机 Z；在配方里记录 `calib_z`，换 Z 时强制重标。
3. **7~9 点 + 双向接近**：提高 A 的稳健性，减小反向间隙。
4. **去畸变**：如果工作视野覆盖图像的明显边缘区域，先用棋盘格做内参 + 畸变校正，再做四点。
5. **多位置 offset + 联合拟合**：3~5 次放置，取均值/标准差；有条件时用 3.4 的联合模型同时优化 offset 和 A。
6. **置信度门槛 + 失败安全**：`detection.valid` 为 False 时禁止运动；检测不到时回安全位/报警，不要用上一次结果硬走。
7. **抓取后确认**：真空压力/夹爪闭合到位/力矩阈值，或抓取后移到相机下复检；标定再好也需要末端确认。
8. **定期复检**：每天/每班用固定标定物跑一次 `verify_image_to_robot()`，看残差和均值是否漂移；漂移大就重标。
9. **如果倾斜明显**：把模型从仿射升级为单应（8 参数，仍可用同一套对应点），或在标定前把相机调垂直。当前模块没有实现单应，但残差/各向异性指标会提示你。
10. **如果目标种类多/有姿态要求**：换 ArUco/AprilTag 或环形+十字标记，圆检测只作为兜底。

## 9. 需要和你确认的问题

1. **相机光轴是否垂直于载台？** 视野多大？镜头是普通透视还是远心？边缘畸变大概几个像素？
2. **Z 是高度轴（已确认）。** 标定物与实际目标的特征高度差 `h`、相机到标定面的距离 `H` 大概多少？（固定拍摄高度不消除 `h` 的视差）
3. **机械臂是笛卡尔三轴吗？** 控制器返回的坐标单位是 mm 还是脉冲？重复定位精度/反向间隙大概多少？
4. **夹爪是否有旋转/姿态要求？** 圆目标没有方向，如果夹爪需要绕 Z 转，需要额外的标记或 fiducial。
5. **抓取精度目标是多少？** 0.1 mm、0.3 mm 还是 1 mm？这决定了是否需要做高度补偿/去畸变。
6. **标定物能否固定在一个位置不动？** 四点阶段需要移动相机；offset 阶段需要多次放置。现场空间是否允许？
7. **抓取位能否看到目标？** 如果能，`verify_pick(check_grasp_view=True)` 可以做端到端复检；如果夹爪会遮挡，只能靠外部传感器。
8. **现场光照是否稳定？** 是否有反光/阴影/背景纹理？标定物能否做成哑光？
9. **是否需要绝对图像→载台坐标？** 还是只需要“拍照→抓取”？前者需要额外的接触/已知点基准。
10. **四张图和四个位姿是否已经成对保存？** 纯 API 只需要 `images` 和 `robot_points`；如果已有采集界面，直接调用即可。

## 10. API 速查

### 10.1 离线标定（主 API，不需要机器人）

```python
import cv2
from measure import CircleLocator, calibrate_image_to_robot, fit_image_to_robot

locator = CircleLocator(radius_range=(15, 80), polarity="dark")

# images: 4 张以上、同尺寸；robot_points: 一一对应的 (x, y) 或 (x, y, z)
images = [cv2.imread(path) for path in paths]
robot_points = [(x1, y1, z), (x2, y2, z), (x3, y3, z), (x4, y4, z)]

calibration = calibrate_image_to_robot(images, robot_points, locator=locator)
print(calibration.valid, calibration.warnings)
print(calibration.matrix)          # 3×3 完整仿射
print(calibration.robot_per_pixel) # 2×2 可复用映射

# 如果圆心已经检测好，直接传点
calibration = fit_image_to_robot(
    image_points, robot_points, image_size=(width, height),

```

纯 API 不移动机械臂，不需要 `RobotLink`；`images` 与 `robot_points` 必须数量一致、顺序对应。

### 10.2 可选硬件驱动

```python
from measure import capture_and_calibrate

calibration = capture_and_calibrate(
    robot, capture,
    positions=[(x1, y1, z), (x2, y2, z), (x3, y3, z), (x4, y4, z)],
    locator=locator,
)
```

它按你给的四个位姿移动、拍照、找圆；不做自动探测。离线数据不需要它。

### 10.3 验证、偏移、配方

```python
from measure import (
    calibrate_gripper_offset,
    verify_image_to_robot,
    verify_pick,
    RobotPickRecipe,
)

report = verify_image_to_robot(robot, capture, calibration, locator=locator)
offset = calibrate_gripper_offset(
    robot, capture, calibration, place_pose=release_pose, locator=locator,
)
recipe = RobotPickRecipe(calibration, offset, locator)
recipe.save("pick_recipe.json")

det = recipe.detect(image)
if det.valid and recipe.validate()["valid"]:
    grasp = recipe.grasp_pose(robot.get_position(), det.center, z=grasp_z)
    robot.move_to(grasp[0], grasp[1], grasp[2])
```

接口契约：

- `capture_and_calibrate` / `verify_image_to_robot` / `calibrate_gripper_offset` 是可选硬件驱动；主标定路径是纯函数；
- `robot.get_position()` 返回 `(x, y[, z])`，Z 是高度；`move_to(x, y, z=None)` 必须阻塞到位；
- `capture()` 每次返回一帧新的灰度或 BGR 图像；
- 视觉拍照的 Z 建议固定，并与 `calibration.calib_z` 一致；偏移标定会在 Z 明显偏离时警告；
- 控制器只支持 `move_to(x, y)` 时，用 `CallableRobot` 包一层，忽略 `z`。

关键方法：

- `ImageRobotCalibration.servo_delta(p)` → `A·(c − p)`；
- `ImageRobotCalibration.center_pose(pose, p)` → `pose + A·(c − p)`；
- `CameraGripperOffset.apply(pose)` → `pose + offset`；
- `RobotPickRecipe.pick_delta(p)` → `A·(c − p) + offset`（一次移动）；
- `RobotPickRecipe.expected_uv_at_grasp()` → `c + A⁻¹·offset`（抓取位复检用）。
